せん断/ストレッチ エディタ 仕様解説

1. はじめに

このドキュメントは、開発された「せん断/ストレッチ エディタ」の操作方法、主要な機能、およびその実装について解説するものです。主にプロジェクトメンバーが仕様を理解し、今後の開発や改修に役立てることを目的としています。

このエディタは、Three.jsを用いて単一のブロックに対し、StormworksのXML編集で可能な非直交変形（せん断・ストレッチ）をマウス操作で直感的に行うことを目指したプロトタイプです。以下の主要な機能を持ちます:

  • マウスドラッグによるせん断 (Shear) 変形
  • Shift + マウスドラッグによるストレッチ (Stretch) 変形
  • 変形中のゴーストプレビュー表示（整数化・制限適用後の形状を半透明で表示）
  • Stormworksの仕様に合わせた行列要素の整数化
  • 変形結果が潰れて操作不能になることを防ぐ最小厚み・最小体積制限
  • 現在の（スナップ後の）回転行列表示

2. 操作方法

  • 視点回転: マウスの右ボタンを押しながらドラッグします。
  • 視点移動 (パン): マウスの中ボタン（ホイールクリック）を押しながらドラッグします。
  • ズーム: マウスホイールを回転させます。
  • せん断 (Shear) 変形:
    1. 変形させたいブロックの面にマウスカーソルを合わせます。
    2. マウスの左ボタンを押しながらドラッグします。
    3. 選択した面が、スクリーン（画面）に平行な仮想平面上をマウスカーソルに追従するように移動し、ブロック全体がせん断変形します。
  • ストレッチ (Stretch) 変形:
    1. 変形させたいブロックの面にマウスカーソルを合わせます。
    2. キーボードの Shiftキー を押しながら、マウスの左ボタンでドラッグします。
    3. マウスのスクリーン上の動きが、選択した面の法線方向への移動量に変換され、ブロックがその方向に伸縮します。面の向き（カメラ側か奥側か）に応じて、マウスの上下に対する伸縮方向が直感的に調整されます。
  • 変形の確定: マウスの左ボタンを離すと、変形が確定します。ゴースト表示（半透明）されていたスナップ後の形状が、最終的なブロックの形状となります。
  • リセット: 左上の「ブロックをリセット」ボタンをクリックすると、ブロックの形状が初期の立方体に戻ります。
  • 行列確認: 左上の「確定後の行列 (r):」欄に、現在の（スナップ後の）ブロックの回転・スケール・せん断を表す行列（左上3x3部分）がカンマ区切りで表示されます。

3. 主要な機能と実装

3.1. 基本構成と初期化 (`init` 関数)

このエディタは `three.js` ライブラリをベースに構築されています。カメラ操作には `OrbitControls` を利用しています。

主な構成要素は以下の通りです:

  • シーン (`scene`): 全ての3Dオブジェクト、ライト、ヘルパーを含む空間。
  • カメラ (`camera`): ユーザーの視点となる `PerspectiveCamera`。
  • レンダラー (`renderer`): シーンを解釈し、Canvasに描画する `WebGLRenderer`。
  • カメラコントロール (`controls`): マウスによる視点操作を可能にする `OrbitControls`。
  • ライト: シーンを照らす `AmbientLight` (環境光) と `DirectionalLight` (平行光源)。
  • ヘルパー: 位置関係を分かりやすくするための `GridHelper` と `AxesHelper`。
  • ブロック (`block`): ユーザーが操作するメインのブロック。リアルタイム（スナップ前）の変形を表示し、不透明。
  • ゴーストブロック (`ghostBlock`): スナップ後（整数化・制限適用後）の形状をプレビュー表示するためのブロック。半透明で、ドラッグ中のみ表示。
  • 初期行列 (`initialMatrix`): ブロックのリセット時に使用する、初期状態の行列。

3.2. ドラッグ操作の検出と状態管理

ユーザーがCanvas上でマウス操作を行うと、以下のイベントハンドラが呼び出されます:

  • `onPointerDown` (マウス左ボタン押下):
    • マウスカーソル下のブロック面情報を `getIntersectedFace` で取得します。
    • 面が見つかれば、ドラッグ状態フラグ `dragState.isDragging` を `true` に設定します。
    • Shiftキーの状態に応じて操作モード (`dragState.mode`) を 'shear' または 'stretch' に設定します。
    • ドラッグ開始に必要な情報（開始点、マウス座標、面情報、開始時の行列など）を `dragState` オブジェクトに保存します。
    • せん断モードの場合は、カメラに垂直な基準平面 `dragPlaneCameraNormal` と、その平面上の開始点 `dragStartPointOnPlane` を計算します。
    • ゴーストブロックを表示 (`ghostBlock.visible = true`) し、現在のブロックの状態に同期させます。
    • カメラ操作を一時的に無効化 (`controls.enabled = false`) します。
  • `onPointerMove` (マウス移動):
    • `dragState.isDragging` が `true` の場合のみ処理を実行します。
    • 現在のマウス座標を `dragState.currentMouse` に更新し、前回の座標を `dragState.lastMouse` に保存します。
    • 現在の `dragState.mode` に応じて `applyShear` または `applyStretch` 関数を呼び出し、ブロックの変形計算と行列更新を行います。
    • 行列表示 `updateMatrixDisplay` を呼び出します。
  • `onPointerUp` (マウス左ボタン解放):
    • `dragState.isDragging` が `true` の場合のみ処理を実行します。
    • 最終的なブロックの状態を、ゴーストブロック（スナップ済み）の状態 (`ghostBlock.matrix`) に確定させます (`block.matrix.copy(...)`)。
    • ゴーストブロックを非表示 (`ghostBlock.visible = false`) にします。
    • `dragState` をリセットし、カメラ操作を再度有効化 (`controls.enabled = true`) します。

関連コード (`dragState` オブジェクト定義):


// ドラッグ操作の状態管理
const dragState = {
    isDragging: false,                      // ドラッグ中か否か
    mode: null,                             // 現在の操作モード ('shear' または 'stretch')
    startPoint: new THREE.Vector3(),        // ドラッグ開始時のブロック面上の交点 (ワールド座標)
    startMouse: new THREE.Vector2(),        // ドラッグ開始時のマウス座標 (NDC)
    currentMouse: new THREE.Vector2(),      // 現在のマウス座標 (NDC)
    lastMouse: new THREE.Vector2(),         // 1フレーム前のマウス座標 (NDC)
    face: null,                             // ドラッグ中の面情報 { normal, materialIndex, axisInfo, center }
    dragPlaneCameraNormal: new THREE.Plane(), // せん断操作で使用するカメラに垂直な平面
    dragStartPointOnPlane: new THREE.Vector3(), // せん断操作のドラッグ開始点 (上記平面上)
    initialBlockMatrix: new THREE.Matrix4(), // ドラッグ開始時のブロック行列
};
3.3. 面情報の取得 (`getIntersectedFace` 他)

ドラッグ操作を開始するためには、まずマウスカーソル下のブロック面を特定する必要があります。これは `getIntersectedFace` 関数で行われます。

  1. Raycasting: `raycaster.setFromCamera(mouse, camera)` でマウス位置からレイを生成し、`raycaster.intersectObject(block)` で不透明なブロック (`block`) との交差判定を行います。
  2. 交差情報の取得: 交差があれば、最初の交差点情報 `intersects[0]` から、交差点のワールド座標 (`intersection.point`) と、交差した面の情報 (`intersection.face`) を取得します。
  3. ワールド法線の計算: 面のローカル法線 (`intersection.face.normal`) を、ブロックの現在のワールド行列 (`block.matrixWorld`) を使ってワールド座標系での法線ベクトルに変換し、正規化します。縮退により法線が計算できない場合は `null` を返します。
  4. ローカル軸情報の取得: 計算したワールド法線とブロックの行列を使って `getLocalAxisInfoFromWorldNormal` 関数を呼び出し、その面がブロックのローカル座標系でどの軸 (X, Y, Z) に対応し、どちらの向き (+ or -) を向いているかを示す情報 (`{ axisIndex, sign }`) を取得します。
  5. 面の中心座標の計算: 得られたローカル軸情報 (`axisInfo`) とブロックの行列を使って `getFaceCenterWorld` 関数を呼び出し、その面のワールド空間での中心座標を計算します。これは、新しいせん断ロジックの基準平面を設定するために使用されます。
  6. 結果の返却: 上記で得られた情報（交点、ワールド法線、マテリアルインデックス、ローカル軸情報、面の中心座標）をまとめてオブジェクトとして返します。

関連コード (`getIntersectedFace` 関数):

3.4. せん断 (Shear) 変形 (`applyShear`)

この操作は、「選択した面を、スクリーンに平行な平面上でマウスカーソルに追従させる」ようにブロックを変形させます。

処理の流れ (`applyShear` 関数内):

  1. 基準平面と現在位置の特定: `onPointerDown` で設定されたカメラ垂直平面 (`dragPlaneCameraNormal`) と、現在のマウス座標 (`currentMouse`) から、平面上の現在の交点 (`currentPointOnPlane`) を `intersectPlane` で計算します。
  2. 移動ベクトルの計算: 平面上のドラッグ開始点 (`dragStartPointOnPlane`) から現在の交点 (`currentPointOnPlane`) へのベクトル (`dragVector`) を計算します。これが、スクリーン上でマウスをどれだけ動かしたかをワールド空間で表すベクトルになります。
  3. 変形の適用:
    • ドラッグ開始時の行列 (`initialBlockMatrix`) をコピーします。
    • 操作面のローカル軸インデックス (`normalAxisIndex`) と向き (`sign`) を取得します。
    • 対応する基底ベクトル (`normalBasis`) を取得します。
    • normalBasis.addScaledVector(dragVector, sign) を実行します。これにより、スクリーン上の移動ベクトルが、面の向きに応じてスケーリングされ、基底ベクトルに加算されます。結果として、面がスクリーンと平行に移動するような変形が起こります。
    • 新しい基底ベクトルを `setBasisVector` で行列に設定します。
  4. 体積チェックと更新: 更新後の行列 (`matrixToUpdate`) の行列式の絶対値が `MIN_VOLUME_THRESHOLD` 以上かチェックします。
    • **OKの場合:** `block.matrix` を更新（スナップ前）。`matrixToUpdate` を `roundMatrixElements` で整数化・クランプし、`ghostBlock.matrix` を更新。
    • **NGの場合:** 行列を更新せず、コンソールに警告を出力します。

関連コード (`applyShear` 関数):


function applyShear(dragInfo) {
    const { face, dragStartPointOnPlane, currentMouse, initialBlockMatrix, dragPlaneCameraNormal } = dragInfo;
    if (!face || !face.axisInfo || !dragStartPointOnPlane) return;

    // 1. Calculate current intersection on the camera-normal plane
    const currentPointOnPlane = intersectPlane(currentMouse, dragPlaneCameraNormal, _vec);
    if (!currentPointOnPlane) return;

    // 2. Calculate the drag vector on that plane
    const dragVector = _vec2.copy(currentPointOnPlane).sub(dragStartPointOnPlane);

    // 3. Apply this drag vector to the initial matrix's basis vector
    const matrixToUpdate = initialBlockMatrix.clone();
    const normalAxisIndex = face.axisInfo.axisIndex;
    const sign = face.axisInfo.sign;
    const normalBasis = getBasisVector(matrixToUpdate, normalAxisIndex, _vec3);

    // Add the calculated dragVector (scaled by face sign)
    normalBasis.addScaledVector(dragVector, sign);
    setBasisVector(matrixToUpdate, normalAxisIndex, normalBasis);

    // 5. Check determinant before applying
    if (Math.abs(matrixToUpdate.determinant()) >= MIN_VOLUME_THRESHOLD) {
        block.matrix.copy(matrixToUpdate);        // Update realtime block
        roundMatrixElements(matrixToUpdate);      // Round and clamp for ghost
        ghostBlock.matrix.copy(matrixToUpdate);   // Update ghost block
    } else {
        console.warn("Shear resulted in near-zero volume. Operation limited.");
    }
}
3.5. ストレッチ (Stretch) 変形 (`applyStretch`)

この操作は、「マウスのスクリーン上の動きを、操作している面の法線方向への『押し引き』量に変換し、ブロックを伸縮させる」ことを目指します。

処理の流れ (`applyStretch` 関数内):

  1. スクリーン移動量の計算: 前フレームからのマウスのスクリーン座標の差分 (`deltaX`, `deltaY`) を計算します。
  2. ワールド移動ベクトルの計算: `deltaX`, `deltaY` と現在のカメラの向きから、ワールド空間でのマウスの移動ベクトル `screenMoveVector` を計算します。
  3. 法線方向への射影: `screenMoveVector` を、操作対象の面の現在のワールド法線ベクトル (`face.normal`) に射影し、法線方向への移動量 `mouseMoveAlongNormal` を計算します。これが「押し引き」の強さを表します。
  4. ストレッチ量の決定: `mouseMoveAlongNormal` に感度 `STRETCH_SENSITIVITY` を掛けて、最終的なストレッチ量 `stretchAmount` を決定します。
  5. 新しい長さの計算:
    • 現在のブロック行列 (`block.matrix`) をコピーします (`matrixToUpdate`)。
    • 操作面のローカル軸 (`normalAxisIndex`) に対応する基底ベクトル (`basisVector`) を取得します。
    • 現在の長さ `currentLength = basisVector.length()` を取得します。
    • `newLength = currentLength + stretchAmount` で新しい長さを計算します。
    • 計算された `newLength` を `Math.max(MIN_THICKNESS, newLength)` で最小厚みにクランプします。
  6. 更新の実行（長さが変わった場合）:
    • `newLength` が `currentLength` から十分に変化したか、または `MIN_THICKNESS` にクランプされた場合のみ更新処理に進みます。
    • `basisVector.setLength(newLength)` で基底ベクトルの長さを更新します。
    • 更新した基底ベクトルを `setBasisVector` で `matrixToUpdate` に書き戻します。
  7. 体積チェックと更新: 更新後の行列 (`matrixToUpdate`) の行列式の絶対値が `MIN_VOLUME_THRESHOLD` 以上かチェックします。
    • **OKの場合:** `block.matrix` を更新（スナップ前）。`matrixToUpdate` を `roundMatrixElements` で整数化・クランプし、`ghostBlock.matrix` を更新。
    • **NGの場合:** 行列を更新せず、コンソールに警告を出力します。

             block.matrix.copy(matrixToUpdate);
             roundMatrixElements(matrixToUpdate);
             ghostBlock.matrix.copy(matrixToUpdate);
         } else {
             console.warn("Stretch resulted in near-zero volume. Operation limited.");
         }
     }
 }
3.6. ゴーストプレビュー

ユーザーが変形操作中に、最終的に確定される形状（グリッドスナップや制限が適用された後）を視覚的に確認できるように、半透明の「ゴースト」ブロックを表示します。

  • オブジェクト: 不透明な `block` とは別に、半透明マテリアルを持つ `ghostBlock` が用意されています。
  • 表示タイミング: `onPointerDown` でドラッグが開始されると `ghostBlock.visible = true` となり、`onPointerUp` でドラッグが終了すると `ghostBlock.visible = false` となります。
  • 形状の同期:
    • ドラッグ開始時 (`onPointerDown`) に、`ghostBlock` の行列は `block` の現在の行列に同期され、すぐに `roundMatrixElements` でスナップされます。
    • ドラッグ中 (`onPointerMove` -> `applyShear`/`applyStretch`) に、`block` の行列がスナップ前のリアルタイムな変形を反映するのに対し、`ghostBlock` の行列は `roundMatrixElements` でスナップされた後の状態を反映します。
    • ドラッグ終了時 (`onPointerUp`) に、`block` の行列が最終的な `ghostBlock` の行列に設定され、見た目が一致した上でゴーストが消えます。
3.7. グリッドスナップと体積制限 (`roundMatrixElements`, `MIN_VOLUME_THRESHOLD`)

Stormworksの仕様に合わせて、ブロックの形状が特定の制約を満たすように調整する処理です。

  • 整数行列 (Grid Snap): Stormworksの回転/スケール行列の要素は整数であるため、`roundMatrixElements` 関数内で `Math.round()` を使って行列の主要な要素を整数に丸めています。これが実質的なグリッドスナップとして機能します。
  • 最小厚み (`MIN_THICKNESS`): 整数化によって基底ベクトルの長さがゼロ（または非常に小さく）なることを防ぐため、`roundMatrixElements` 内で、整数化後に各基底ベクトルの長さをチェックし、`MIN_THICKNESS` 未満であれば、その長さを強制的に `MIN_THICKNESS` に修正（クランプ）します。これにより、ブロックが完全に見えなくなったり、Raycasting が失敗したりするリスクを低減します。注意: クランプ処理により、最終的な行列要素が厳密には整数でなくなる場合がありますが、これは最小厚みを維持するための仕様です。
  • 最小体積 (`MIN_VOLUME_THRESHOLD`): せん断変形などによってブロックが潰れて体積がゼロ（縮退）になるのを防ぐため、`applyShear` と `applyStretch` の中で、変形後の行列の行列式 (`determinant`) の絶対値を計算し、それが `MIN_VOLUME_THRESHOLD` 未満になるような変形は適用しないように制限しています。

関連コード (`roundMatrixElements` 関数):


function roundMatrixElements(matrix) {
    const te = matrix.elements;

    // 1. First, round the relevant elements to integers
    // ... (Math.round() for elements 0,1,2, 4,5,6, 8,9,10) ...

    // 2. Then, check the length of each basis vector AFTER rounding and clamp if needed
    for (let i = 0; i < 3; i++) {
        const basis = getBasisVector(matrix, i, _vec);
        const lengthSq = basis.lengthSq();
        if (lengthSq < MIN_THICKNESS * MIN_THICKNESS) {
            if (lengthSq > 1e-9) { basis.setLength(MIN_THICKNESS); }
            else { basis.set(0,0,0).setComponent(i, MIN_THICKNESS); }
            setBasisVector(matrix, i, basis); // Set clamped vector back
        }
    }
}
3.8. 行列表示 (`updateMatrixDisplay`, `matrixToRotationString`)

現在のブロックの確定後の形状を表す回転・スケール・せん断行列（左上3x3）をUIに表示します。

  • 表示タイミング: ドラッグ中およびドラッグ終了時、リセット時に `updateMatrixDisplay` 関数が呼び出されます。
  • 表示内容: ドラッグ中は `ghostBlock`（スナップ後）の行列を、ドラッグ終了後や初期状態では `block` の行列を `matrixToRotationString` 関数でフォーマットして表示します。
  • `matrixToRotationString` 関数:
    • 入力された行列をコピーし、`roundMatrixElements` を適用して表示用の一時的な丸め・クランプ処理を行います（元の行列は変更しません）。
    • 丸め・クランプ後の行列要素 `te[0]` から `te[10]` まで（左上3x3部分）を、StormworksのXMLで使われる列優先順 (`r11,r21,r31,r12,r22,r32,r13,r23,r33`) でカンマ区切りの文字列に変換して返します。

関連コード (`matrixToRotationString` 関数):


function matrixToRotationString(matrix) {
    _mat.copy(matrix); // Copy matrix to avoid modifying the original
    roundMatrixElements(_mat); // Apply rounding and clamping for display consistency
    const te = _mat.elements;
    return [
        te[0], te[1], te[2], // Column 1 (X Basis)
        te[4], te[5], te[6], // Column 2 (Y Basis)
        te[8], te[9], te[10] // Column 3 (Z Basis)
    ].join(',');
}

5. まとめと今後の課題

このエディタは、マウス操作による直感的なせん断・ストレッチ変形、ゴーストプレビューによるスナップ結果の視覚化、およびStormworksの仕様に合わせた整数行列・最小厚み・体積制限を実現したプロトタイプです。

今後の課題・改善点候補:

  • 縮退時のインタラクション改善: 現在は縮退（体積ゼロ）に近い状態になると操作を制限していますが、Raycastingが失敗しやすくなる問題は残っています。縮退状態でも安定して面を選択し、操作を再開できるような、より高度なインタラクションの実装が考えられます（例: バウンディングボックスや隣接面を利用した選択）。
  • パフォーマンス: ブロック数が増えた場合のパフォーマンスは考慮されていません。InstancedMeshなどを使用した最適化が必要です。
  • 操作モードの追加: 回転、移動、複数ブロック選択、コンポーネント接続など、実際のStormworksエディタにあるような機能の追加。
  • UI/UXの改善: 現在の操作モードや選択状態をより分かりやすく表示するUI、アンドゥ/リドゥ機能など。
  • XML入出力: 現在のブロック状態をStormworksのビークルXML形式で保存・読み込みする機能。
